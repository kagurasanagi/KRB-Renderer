# KRB Renderer 使い方の詳細

画面の操作・コマンドライン・設定ファイル・材質など、[README](../README.md) より詳しい説明です。

## リアルタイム表示（`krbr <pcb>` / `krbr view <pcb>`）

**画面（WebView2）**：メニュー・ボタン列・ステータスバー・設定パネル・警告の帯・材質エディタ・説明の吹き出し・「KRB Renderer について」・「動画を書き出す」・「KiCad プラグイン」の窓は WebView2（Tauri の WebView の部品 `wry`）で描きます。3D 表示は今までどおり Vulkan で描き、その上下・右・上に WebView を子ウィンドウとして重ねます（`krbr-app/web/` の HTML・CSS・JavaScript を exe に埋め込む。材質の見本と部品のプレビューの画像は `http://krbr.localhost/` で渡す。データは全体用キャッシュの `webview2\`）。WebView2 の分、メモリが 300〜450 MB ほど増えます。WebView2 Runtime が無いときは 3D 表示とキーの操作だけになり、入れ方を画面に出します（隠したウィンドウのテストも 3D 表示だけ）。

起動するとすぐウィンドウを出し、基板は裏のスレッドで読み込みます（その間に GPU の準備も進む）。画面の用意ができるまでは、ウィンドウの真ん中に進み具合のバーと、今の段階（1 行）を出します。WebView2 の画面は、いつも見えるもの（ボタン列・ステータスバー・設定パネル）を作ったら見せ、残り（メニュー・説明の吹き出し・材質エディタなど）はその後に作ります。読めなかったときは、ウィンドウを開いたまま知らせます。

**起動のしかた**：`KRB-Renderer.exe`（コンソールを持たない小さな起動役。同じフォルダの `krbr.exe` をコンソール無しで起動する）をダブルクリックするか、そのアイコンに `.kicad_pcb` を落とします。`krbr.exe` をエクスプローラーから開いたときも、コンソールの無いプロセスで起動し直します（Windows Terminal の窓はプログラムから隠せないため。窓が一瞬出る）。コンソール無しで起動に失敗したときは、最近のログを窓で知らせます。

**最近使った基板**：「ファイル → 最近使った基板」に新しい順に 10 個（`state.toml` の `[ui] recent_boards`）。**ドラッグ＆ドロップ**：ウィンドウ（3D 表示・パネルの上のどこでも）に `.kicad_pcb`（`.kicad_pro` なら同じ名前の基板）を落とすと開き、`.hdr` / `.exr` を落とすと環境マップにします。

**描画ロック**（ボタン列の「ロック」、`L`、「表示 → 描画をロック」）：時間をかけている画像を守ります。ロック中は視点が動かず（ドラッグ・ホイール・Ctrl ＋クリック・真上から／全体を表示などは効かない）、設定の変更・基板の保存による読み直し・材質の割り当て・環境マップの読み込みは、ロックを解除するまで待たせます（解除すると反映して描き直す）。ウィンドウの大きさを変えても描画の大きさは変えず、今の画像を縮めて見せます。露出・グロー・ノイズ除去・表示の種類など、累積に関わらない表示の設定は効きます。最大 spp を上げると、そのまま積み足します。3D 表示の上端の帯に、ロック中であることと「ロックを解除」のボタンを出します。

**動画の書き出し**（「ファイル → 動画を書き出す…」）：カメラを動かしながら 1 コマずつ決まったサンプル数まで積み、MP4（H.264）にします。動きは「1 周（ターンテーブル。等速で最初と最後がつながる）」「首振り（±30°）」「1 周＋上下（±10°）」。長さ・フレームレート（24 / 30 / 60）・サイズ（1920×1080、1280×720、1080×1080、1080×1350、3840×2160）・1 コマのサンプル数（32〜1024）・ノイズ除去・画質（高画質 / 標準 / 小さく：1 画素・1 フレームあたり 0.2 / 0.1 / 0.05 ビット）・回る中心（基板の中心 / 今の注視点）を選べます。今の視点（向き・距離・画角）から始め、書き出しの間は描画ロックと同じく操作を受けません（帯の「中止」で、そこまでのコマで閉じる）。かかる時間の見込みは、今の描画の速さから出します。エンコードは Windows に入っている Media Foundation の H.264 エンコーダー（FFmpeg は要らない。GPU のエンコーダーがあれば使う）。色は BT.709 の NV12 にして渡します。
時間方向のちらつき：OIDN は 1 枚ずつのノイズ除去で、時間方向は見ません。どのコマも同じ乱数の列（画素・サンプル番号・シードが同じ）で積むので、残ったノイズは画面に張り付いた細かな模様になり、コマごとに跳ねる「ちらつき」にはなりにくくなっています。動く部分（反射・映り込み）で気になるときは、1 コマのサンプル数を増やしてください（ノイズ除去ありで 128〜256 が目安）。

フレームごとにサンプルを積み増して表示します。1フレームに積むサンプル数は、GPU のタイムスタンプで測った時間が約 10 ms に収まるように自動で調整します。最大のサンプル数（既定 2^12 = 4096）まで積むと描画を止め、GPU を休ませて入力を待ちます。最大はパネルで 2 の何乗か（2^4 = 16 〜 2^16 = 65536）で選びます。`--spp` を指定すると、それ以上で最も近い 2 の累乗になります。ノイズはサンプル数の平方根でしか減らない（半分にするには 4 倍の時間）ので、1 段上げるごとの変化は小さくなります。

**ボタン列**（メニューの下。大きめのアイコンと、その下に名前）：

| ボタン | 内容 |
|---|---|
| 一時停止 / 再開 / 完了 | サンプルの積み足しを止める・再開する（`P`。下記「一時停止」）。最大 spp に達したら「完了」になり押せない |
| 真上から / 真裏から | 真上・真裏から、基板全体が入る構図にする（画角は今のまま）。真上は KiCad の画面と同じ向き、真裏は KiCad で裏から見たときと同じく左右が反転した向き。そこからドラッグしても向きは跳ばない |
| 全体を表示 | 今の向き（仰角・方位・画角）のまま、基板全体がちょうど画面に入る位置へカメラを動かす（`F`、メニューの「表示」）。ピントは注視点に戻す。基板が画面の外に出たときは、3D 表示の上にこのボタンを案内する |
| 表面実装 / スルーホール | その種類の部品を表示する・隠す（押してある色なら表示中、斜線なら隠している）。種類はフットプリントの属性（`smd` / `through_hole`）で、属性が無ければパッドで決める（スルーホールのパッドがあればスルーホール）。どちらでもない部品と基板はいつも表示。隠した部品は光線が通り抜け、光る部品も光らない（形状は作り直さない。`krbr-render` の `GpuScene::set_visible_mask`）。クリックでも選べない |
| ノイズ除去 | ノイズ除去（OIDN）した画像を表示する（パネルの「ノイズ除去 (OIDN)」と同じ） |

同じ操作はメニューの「表示」にもあります。表示・非表示は基板ごとに覚えます。

キーの割り当ては 1 つの表（`krbr-app` の `viewer.rs` の `KEY_BINDINGS`）にあり、キー処理・メニューの「ヘルプ」・起動時のログはどれもそこから作ります。

**描画のサイズとレンダリングの比率**（メニューの「表示」、パネルの「表示」の欄、`--render-size WxH|fit` / `--render-ratio`）：

- 描画のサイズは「ウィンドウに合わせる」か、決まったサイズ（1280×720、1920×1080、2560×1440、3840×2160、1080×1080、1080×1350、1200×800）です。`--render-size` には任意の `WxH`（1 辺 16384 まで）も書けます。読めない値はエラーで止めます（黙って「ウィンドウに合わせる」にはしない）。
- レンダリングの比率は、レンダリングの解像度 ÷ 表示の大きさです（メニューは ×0.25 / ×0.5 / ×1 / ×1.5 / ×2。`--render-ratio` は 0.1〜4 の任意の値）。
- **決まったサイズ**では、3D 表示の領域が「描画のサイズ ÷ 比率」になるように、ウィンドウの大きさを変えます（例：3840×2160・×2 なら領域は 1920×1080 で、4K で描いて縮小表示）。画面に入らないときは、入るまで比率を上げて知らせます。その後で手でウィンドウの大きさを変えたときは、描画の解像度はそのままで、縦横比を保って領域に収めて表示します。
- **ウィンドウに合わせる**では、レンダリングの解像度は「3D 表示の領域 × 比率」です。×0.5 にすると、1 サンプルの時間が約 1/4 になって操作が軽くなります（表示は拡大するので粗くなる）。
- `S` で保存する画像はレンダリングの解像度です。描画のサイズと比率は基板ごとに覚え、決まったサイズを選んでいれば `render` もその大きさで書き出します（`--width` / `--height` を付けたらコマンドラインが勝つ）。

画面の下端の**ステータスバー**に、次を表示します。

- 1 行目：状態（レンダリング中 / 完了 / 一時停止中）、積んだサンプル数と進み具合、**経過時間**（今の累積を始めてからレンダリングにかかった時間。一時停止の間と完了後は数えず、視点などを変えて累積をやり直すと 0 から）、**1 サンプルあたりの平均**（経過時間 ÷ サンプル数と、GPU がサンプルを描いた時間だけの平均。完了後は変わらない）、残りの予想時間
- 2 行目：積分器と色の計算、描画の解像度と表示の倍率、露出、カメラの距離（注視点から）、GPU の名前と方式（ray query / ray tracing pipeline）、読み直し・kicad-cli・3D モデルの分割の状態と、最後の更新の知らせ
**表示の言語**（いまは英語と日本語）は、次の順で決めます。訳の無い言語なら英語で表示します。

1. `--lang ja` か、環境変数 `KRBR_LANG`
2. メニューの「設定」→「言語」で選んだもの（`%APPDATA%\krbr\state.toml` に覚える。「自動」で 3 以降に戻る）
3. KiCad で選んだ言語（`kicad_common.json` の `system.language`。KiCad が「Default」なら次へ）
4. OS の言語

ログとコマンドラインの説明は英語です。KiCad のプラグインのボタンとメッセージは、KiCad の表示の言語に合わせます。翻訳は `rust/crates/krbr-app/i18n/<言語>/krbr-app.ftl`（[Fluent](https://projectfluent.org/) の形式、英語が基準）で、exe に埋め込みます。言語を足すときは、英語のファイルを写して訳し、`krbr-app/src/i18n.rs` の `LANGUAGES` に加えます。

開発用に、非表示のウィンドウで描いて終了するテストモードがあります（`--test-frames N --screenshot path [--test-orbit 度]`）。画面には出ず、フォーカスも奪いません。途中で UI の操作をしたことにする `--test-reload` / `--test-pick` / `--test-assign` / `--test-mask` / `--test-save-as` / `--test-reset-settings` / `--test-open` / `--test-view top|bottom` / `--test-hide smd,tht,solder` もあり、決まったフレームで要求として流し込みます（`viewer.rs` の `TestHooks`）。

## 保存の監視と差分更新

ビューア（`--no-watch` で無効）と `krbr watch` は、`.kicad_pcb` の保存を見張って自動で読み直します。

- 基板のフォルダの変更通知（`notify`。Windows は ReadDirectoryChangesW）で保存を知り、更新日時とサイズで確かめます。KiCad 10 以降の保存（同じフォルダの一時ファイルに書いてから名前を変えて置き換える）は、書き終えたファイルなので待たずに読みます。そのまま書き込む保存（KiCad 9 まで）は、変化が 200 ms 止まってから読みます（書き込みの途中では読まない）。通知を取りこぼしたときや使えない場所（ネットワークドライブなど）のために、1 秒ごと（通知が使えなければ 100 ms ごと）にも更新日時を調べます。
- 部品・配線・ビア・ベタ・図形ごとに、UUID と S 式のハッシュと範囲を持ち、前回と比べて**変わった項目の新旧の範囲**だけを作り直します（`krbr-kicad` の `diff_boards`）。外形や層構成が変わったときは全体を作り直します。
- 凹凸メッシュは 8 mm 角のタイルに分けて持ち（`krbr-geom` の `ReliefTileCache`）、範囲にかかるタイルだけを並列で作り直します。部品を 1 つ動かすと、200 枚のうち 4 枚程度です。
- 読み直しは裏のスレッドで行います。読み直し中と、変更の件数・作り直したタイルの数・かかった時間は、設定パネルの上に出ます。読み直しの間に変えたレジストの色は、差し替えのときに反映します。
- GPU の形状（BLAS/TLAS）はまとめて作り直します（数十 ms）。環境マップは送り直しません。
- キャッシュにない 3D モデルは、まず箱で表示し、裏の 1 本のスレッドで分割し終えたら差し替えます。
- 線フォントの文字（シルク・銅箔・マスク）が変わったときは、kicad-cli による描き直しを裏で行い、それまでは前の文字のままです。
- `krbr watch` はウィンドウを開かずに、保存のたびに `--out`（既定 `out\watch.png`）を書き直します（1 回の更新で積むのは `--spp`、既定 32。`--max-updates` 回で終わる。ノイズ除去は既定で有効、`--no-denoise` で無効）。トーンマッピングを GPU で行い、軽く圧縮した PNG（zlib の最も速い設定と Sub フィルタ。圧縮率より書き出しの速さを優先する）を一時ファイル経由で置き換えます。分光モードでもノイズ除去は正しい色でかかります（下記）。

計測（RTX 3080 Ti、1920x1080、32 spp）：0603 のコンデンサを 1.5 mm 動かす保存から画像の更新まで約 0.5 秒（監視の待ち 0.2〜0.3、読み直し 0.15（解析 0.05、タイル 4 枚）、GPU 0.04、描画 0.12、書き出し 0.02）。

## ノイズ除去（OIDN）

`krbr-render` の `denoiser` が Intel Open Image Denoise（RT フィルタ、HDR、補助情報としてアルベドと法線）を使います。OIDN の DLL（`OpenImageDenoise.dll` ほか一式）は実行時に読み、exe と同じフォルダの `dll\oidn\`、exe と同じフォルダ、開発中は `<リポジトリ>\third_party\oidn\bin\` の順に探します（無ければノイズ除去だけが使えず、ほかはそのまま動きます）。

- Vulkan のデバイスと同じ GPU（UUID で選ぶ）の CUDA デバイスで動かし、Vulkan のバッファを外部メモリ（Win32 ハンドル、`VK_KHR_external_memory_win32`）として OIDN と共有します。CPU を経由する転送はありません。共有できない環境では CPU デバイスに切り替えます（開発用に `KRBR_DENOISE_DEVICE=cpu` で強制できる）。
- 累積画像をサンプル数で割って入力を作るシェーダ（`denoise_prep.comp`）→ OIDN → 結果を画像へ写し、表示用のトーンマッピングにつなぎます。
- **強さ**：OIDN 自体には強さの設定が無いので、ノイズ除去した画像と元の画像を混ぜる割合として調整します（パネルのスライダー、`--denoise-strength`。0〜1、既定 1 で OIDN の結果そのまま。下げると細部やざらつきが少し残る）。混ぜる処理は軽い（`shaders/denoise_blend.comp`）ので、ビューアではスライダーを動かすとすぐ反映されます。
- ビューア：既定で無効（`--denoise` かパネルの「ノイズ除去 (OIDN)」で有効にする。OIDN の準備は有効にしたときに初めて行う）。カメラを動かしている間は品質 fast で毎フレーム、止まったら high で 150 ms ごと、収束時にもう一度。`S` を押したとき、ノイズ除去した画像を表示していれば `<名前>_NNN_denoised.png / .exr` も書きます（表示と同じ強さ）。
- 速さ（RTX 3080 Ti）：1920x1080 の high で約 14 ms、960x540 で 5 ms。CPU デバイスでは 960x540 で約 0.2 秒です。4 spp の画像をノイズ除去すると、1024 spp の参照との差の平均が約 70% 減ります（RGB・分光とも）。
  - ノイズ除去が **CPU** になるとき（CUDA が使えない GPU。GTX 1060 など）は 1 回に数秒かかり画面が止まるので、ビューアは**収束時（最大 spp に達したとき）と、`D` キー／パネルの「今かける」のときだけ**かけます（常に品質 high）。それ以外は蓄積中のノイズのある画像をそのまま表示します。
- `krbr watch`：既定で有効（high）。`krbr render --denoise` で `<名前>_denoised.png / .exr` も書き出します。`--no-denoise` で無効にできます。

### 速さの計測（`krbr bench`）

GPU を替えたときなどに、同じ条件でレンダリングの速さを測ります。覚えた設定（パネルの設定・視点・環境マップ）は使わず、条件を固定します：1920x1080、内蔵のスタジオ、自動の構図（仰角 35°・方位 45°・画角 30°）、ピンホール、露出 0、乱数の種 0、ノイズ除去なし。PT（RGB）・PT（分光）・BDPT・VCM のそれぞれで、準備の 8 サンプル（測らない）の後、`--spp`（既定 64）サンプルの時間を測ります。基板の読み込みとシーンの準備の時間は含みません。CPU の優先度は下げません。

結果は `%APPDATA%\krbr\bench.csv` に追記します（日時、GPU、ドライバ、方式、基板とその内容のハッシュ、条件、1 サンプルあたりの時間（ms））。画面には 1 秒あたりのサンプル数（spp/s。大きいほど速い）で表示します。同じ基板（内容が同じもの）・同じ条件で別の GPU の記録があれば、最後のものと比べて何倍速いかを表示します。GPU を替える前に一度測っておけば、替えた後に同じコマンドで比べられます。

**同梱のベンチマークの基板**（`krbr bench` と基板を省く）：`bench\krbr_bench.kicad_pcb`（配布の一式では exe の横、開発中はリポジトリ）を使います。100×70 mm の 4 層基板で、部品 201 個、ビア 276 個、三角形は約 80 万です（BGA-256、LQFP-64、QFN、SOIC、TSSOP、0402〜0805 の受動部品、USB-C、ピンヘッダ、インダクタ、電解コンデンサ、タクトスイッチなど）。

- 環境で結果が変わらないように、次のようにしています。
  - 3D モデルは KiCad 10 の標準ライブラリの STEP だけで、`bench\3dmodels\` に同梱しています（`${KIPRJMOD}/3dmodels/...` で参照）。KiCad が入っていない PC でも、別の版の KiCad の PC でも、同じモデルを読みます。
  - 基板の設定ファイル（`.krbr`）と、全体設定の材質ライブラリ・対応表は読まず、既定値と組み込みの材質だけを使います。
  - kicad-cli は使いません（シルクには線フォントの文字を置いていません）。
- モデルが 1 つでも読めなければ、測らずにエラーで止めます（箱で代えた結果は、ほかの PC と比べられないため）。
- 基板は `python scripts\gen_bench_board.py` で作ります。KiCad のフットプリントとモデルを決まった配置で並べるので、何度作っても同じものになります。作り直して内容が変わると、それまでの記録とは比べられなくなります。ライセンスは `bench\LICENSE.md`（KiCad のライブラリの CC-BY-SA 4.0、例外条項付き）です。

自分の基板を指定したときは、その基板の設定ファイルの項目（最大の深さ・材質など）と kicad-cli を使います。比べる間は設定ファイルを変えないでください。

## GPU の要件と、GTX 1060 での状況

描画には Vulkan 1.3 と `VK_KHR_acceleration_structure` に加えて、**`VK_KHR_ray_query` か `VK_KHR_ray_tracing_pipeline`** のどちらかが必要です。交差判定は `shaders/scene.glsl` の `rawTraceClosest` / `rawOccluded` に閉じていて、GPU に応じて次のどちらかで作ります（本文のシェーダは同じ。`shaders/stage.glsl` で切り替え）。

| 方式 | 使う GPU | 仕組み |
|---|---|---|
| ray query（優先） | RTX など `ray_query` を持つもの | 計算シェーダの中で `rayQueryEXT` を辿る（`<名前>.comp.spv`） |
| ray tracing pipeline | GTX 10 系など `ray_query` が無いもの | 同じ本文をレイ生成シェーダとして組み（`<名前>.rgen.spv`、`-DKRBR_RT_PIPELINE`）、`traceRayEXT` → 最近接ヒット `rt_hit.rchit`（交点の生の情報をペイロードへ）／ミス `rt_miss.rmiss`／影用ミス `rt_shadow.rmiss`。再帰はせず、シェーダバインディングテーブルは `krbr-render` の `kernel.rs` が組む |

| GPU | 状況 |
|---|---|
| RTX 3080 Ti（開発元の PC） | ray query。このドキュメントの時間の数値はここで測ったもの |
| GTX 1060 6GB（別の開発用の PC、ドライバ 581） | `ray_query` なし → ray tracing pipeline。RT コアが無いのでドライバのエミュレーションで、RTX より大きく遅い（下記） |

`krbr probe` でどちらになったかを表示します（`GPU: ... ray tracing pipeline (no ray_query)`）。

GTX 1060 での実測（kachkojir_RK3506G2、135 万三角形、PT、深さ 8）：

| 項目 | 時間 |
|---|---|
| `render` 640x360 | 40 ms/spp |
| `render` / `watch` 1920x1080 | 約 180〜200 ms/spp（32 spp で 6 秒前後） |
| ノイズ除去 1080p（OIDN、CPU の high） | 6〜8 秒 |
| 保存から画像の更新（watch テスト、32 spp、ノイズ除去込み） | 13〜16 秒（RTX 3080 Ti では約 0.5 秒） |

白い炉テスト・積分器の一致・プリズムの分散・カメラの GPU のテスト（[開発者向け](development.md)の「テスト」）は、GTX 1060（ray tracing pipeline 版）で、すべての値が以前の C++ 版と表示の桁まで同じでした。また C++ 版のときに、ray tracing pipeline 版と ray query 版で同じ値になることを確かめています。watch テストの「保存から 1 秒以内」は、`ray_query` を持つ GPU が無い PC では 30 秒に緩めています（仕組みの検証が目的のため）。

そのほか、GTX 1060 では OIDN の CUDA デバイス（Volta 以降が必要）が使えないので、ノイズ除去は CPU（Xeon E3-1290 V2、AVX2 なし）で行われ、1080p の high で 6〜8 秒かかります。VRAM が 6 GB なので、環境マップは 8k ではなく 4k を使ってください。

## 作業中の PC への配慮

- `render` / `probe` / `info` では、ウィンドウ・サーフェス・スワップチェーンを作りません。画像を自動で開くこともしません。
- `view` は収束したら（`--spp` に達したら）描画を止めて入力を待つので、表示したままでも GPU をほとんど使いません。
- CPU の優先度：ウィンドウを持たないコマンド（`render` / `watch` / `geom` / `models`）は、プロセス全体を BELOW_NORMAL で動かします（`--normal-priority` で通常に戻す）。ビューアはプロセスとウィンドウのスレッド（入力・パネル・GPU への投入）を通常のままにし、裏の処理（読み直し・凹凸タイルの作り直し・3D モデルの分割・環境マップの読み込み）のスレッドだけを BELOW_NORMAL にします。ほかのアプリが CPU を使っていても、一時停止などの操作への反応は遅れません。kicad-cli は BELOW_NORMAL で、コンソールを出さずに起動します。
- GPU は、`render` では**グラフィックスを持たない計算専用キュー**を使います。`view` では、画面へ表示できるキューを使います。どちらも `VK_KHR_global_priority` が使えれば **LOW** で作ります。
- 1 サンプルずつ投入して完了を待つので、GPU を長時間占有しません。既定のサンプル数は 64 です。
- `.kicad_pcb`、KiCad のライブラリ・設定は読み取りのみです。
  - kicad-cli はプロジェクトフォルダに `.kicad_prl` を作るので、基板を**一時フォルダへコピーしてから**呼び出します。
- プロジェクトフォルダに書くのは、基板の設定ファイル `<名前>.krbr`（置き場所を「基板の横」にしているとき）と、ビューアで `S` を押したときの画像だけです。`<名前>.krbr` は、`--init`、材質の割り当て、ビューアで覚えた設定のときに書き、手で書いた表とコメントは残します。

## 設定ファイル

| 場所 | 内容 |
|---|---|
| `<基板のフォルダ>\<基板の名前>.krbr`（または `%APPDATA%\krbr\boards\`。下記） | 基板ごとの設定をすべて 1 つの TOML に入れる（下の表） |
| `%APPDATA%\krbr\settings.toml` | 全体の設定（`board_settings`：基板の設定ファイルの置き場所） |
| `%APPDATA%\krbr\state.toml` | 基板によらない記憶（最近使った環境マップ、ビューアのウィンドウ） |
| `%APPDATA%\krbr\materials\*.toml` | 名前付きの材質（OpenPBR）。組み込みの材質に、書いた項目だけ重ねる。ビューアの材質エディタで作った材質は `user.toml` に書く |
| `%APPDATA%\krbr\model_map.toml` | 3D モデルごとの材質（他のプロジェクトと共有）と、色・名前の規則 |
| `%LOCALAPPDATA%\krbr\cache\meshes\` | 3D モデル（STEP の分割結果、VRML）のキャッシュ（キーはファイル内容の XXH64 ＋読み込み器と分割パラメータ） |
| `%LOCALAPPDATA%\krbr\cache\silk\` | kicad-cli による線フォントの文字の SVG のキャッシュ |
| `%LOCALAPPDATA%\krbr\cache\relief\` | 凹凸のタイル（メッシュと距離場）のキャッシュ。基板ごとに 1 つ（数十 MB）、最近の 8 枚分。タイルごとに、その範囲にかかる基板の項目と設定・krbr.exe から作ったキーで引くので、少し直した基板でも変わったタイルだけを作り直す |

ファイルが無ければ既定値を使います。優先順位は「コマンドライン ＞ ビューアで覚えた設定 ＞ 設定ファイル ＞ 既定値」です。

**基板の設定ファイル `<名前>.krbr`**（`krbr-scene` の `board_file.rs`）：

| 表 | 内容 | 書くのは |
|---|---|---|
| `[board]` `[relief]` `[surface]` `[solder]` `[placeholder]` `[paths]` `[kicad_cli]` | 表面処理、レジスト・シルク・基材の色、距離場の解像度、凹凸の厚み、はんだフィレット、代替の箱、モデルのパスの変数・追加検索フォルダ、kicad-cli | 人（`--init` でひな形） |
| `[environment]` `[camera]` `[render]` `[lens]` | 環境マップ・強さ・回転、カメラ、解像度・spp・露出・グロー・積分器、レンズ | 人（`--init` でひな形） |
| `[ref.<部品番号>]` `[[model]]` | 材質の上書き（部品番号ごと・3D モデルごと） | ビューア、`krbr material set` |
| `[remembered]` | ビューアで最後に使った設定（環境マップ、パネルの設定、視点）。消すと上の表の値に戻る | ビューア（`--hdr` を付けた `render` も環境マップを） |

- ファイルが無いときは、ツールが書く必要ができたときに、説明つきのひな形（値は既定値と同じ）から作ります。書き換えるのはその表だけで、手で書いた値・コメント・並びは残します（`toml_edit`）。書式の誤りで読めないファイルには触らず、警告します。
- 中の相対パス（`hdr`、`lens_file`、`model_search_dirs`）は、置き場所によらず基板のフォルダからです。`hdr = ""` / `lens_file = ""` は書かないのと同じです。
- 知らない項目（打ち間違いなど）、型の誤り（数のところに文字列など）、範囲外の値（負の spp など）は、警告を出して、その項目だけ既定値にします（ほかの項目は使う）。名前で選ぶ項目（`integrator`、`[lens] model`、`finish` など）の知らない名前も同じです。
- 色は、設定ファイル（`mask_color`、`silk_color` など）では sRGB、材質ライブラリ（`materials/*.toml`、OpenPBR）ではリニアで書きます。
- **置き場所**：ビューアの「ファイル」→「基板の設定ファイルの置き場所」で、「基板の横」（既定）か「全体設定のフォルダ（`%APPDATA%\krbr\boards\<名前>_<基板のパスのハッシュ>.krbr`。KiCad のフォルダにファイルを増やさない）」を選びます（`settings.toml` の `board_settings = "board"` / `"config_dir"`。すべての基板に効く）。開いている基板のファイルはすぐ移し、ほかの基板のものは次に開いたときに移します。「基板の設定ファイルを表示」でエクスプローラーで開けます。
- **以前の形からの移行**：`<名前>.krbr\` フォルダ（`board.toml` / `environment.toml` / `overrides.toml`）は、見つけたら 1 つのファイルにまとめ、フォルダは `<名前>.krbr.old` に名前を変えて残します（無かったファイルの分はひな形で埋める。フォルダからの相対パスだった `hdr` / `lens_file` は絶対パスにする）。`state.toml` に基板ごとに覚えていたもの（`[boards."<パス>"]`）も、その基板を開いたときに `[remembered]` へ移します。
- 1 つのファイルにした理由：以前は、手で書く設定とツールが書き換える設定をファイルで分けていました（書き換えでコメントが消えないように）。表だけを書き換えるようにしたので分ける必要がなくなり、基板と一緒に持ち運ぶ・バージョン管理するのに 1 つの方が扱いやすいためです。ビューアで覚えた設定も入るので、視点などを変えるたびにファイルが書き換わります（git で管理しているなら差分が出ます）。

### レジストの色

レジストの色は次の順で決まります：`--mask-color` ＞ ビューアで選んで覚えたもの ＞ `<名前>.krbr` の `[board] mask_color` ＞ `.kicad_pcb` の stackup の色（KiCad の基板設定で選んだ色）＞ 緑。

`mask_color` と `--mask-color` には、sRGB の値（`[r, g, b]` / `r,g,b`）のほかに**プリセット名**を書けます。プリセットは色だけでなく、コートの粗さ（光沢／つや消し）と顔料の散乱（透明さ）もまとめて設定します。一覧は `krbr mask list`。

| プリセット | 内容 |
|---|---|
| `green` `red` `blue` `yellow` `purple` `black` `white` `matte-black` | KiCad の stackup の色名と同じもの。stackup に色があれば自動でこれが使われる |
| `jlcpcb-green` `jlcpcb-purple` `jlcpcb-red` `jlcpcb-yellow` `jlcpcb-blue` `jlcpcb-white` `jlcpcb-black` `jlcpcb-matte-black` `jlcpcb-matte-green` | JLCPCB の注文時に選べる色。白・黒は不透明寄り、matte は粗さを上げてある |
| `clear` | 透明なレジスト（色も顔料の散乱も無い）。下の透明な基材と組み合わせると基板が透ける |

**基材**（`--substrate <名前>`、`<名前>.krbr` の `[board] substrate`、ビューアの「表面」→「基材」。基板ごとに覚える）：既定は FR4 です。材質ライブラリの名前を書くと、基材（基板の本体と側面）をその材質にします（例 `glass_frosted` ですりガラスの基板、`ceramic_alumina` でアルミナ基板。ビューアでは透明な材質・宝石・セラミックから選べる）。レジストは基材の上に塗るので、透けて見せるにはレジストも `clear` にします。銅のベタがある基板では、透明なレジストの下に銅がそのまま見えます。内層は形状に無いので描きません。

ビューアでは操作パネルの「表面」→「レジスト」でその場で切り替えられます（材質だけを送り直すので一瞬で、累積はやり直し）。

プリセットはシルクの色も決めます：黄・白のレジストでは黒、それ以外では白。シルクの色は「`<名前>.krbr` の `silk_color` ＞ レジストのプリセットに合わせた色 ＞ `.kicad_pcb` の stackup のシルクの色 ＞ 白」の順で決まります。

名前の大小・区切りは無視します（`JLCPCB Purple`、`jlcpcb:purple` も同じ）。メーカーの色は写真からの目分量で、実測ではありません。プリセットの後に `mask_roughness` / `mask_scatter` を書けば、その項目だけ上書きできます。

```
krbr render board.kicad_pcb --hdr studio.exr --mask-color jlcpcb-purple
```
全体設定とキャッシュの場所は、環境変数 `KRBR_CONFIG_DIR` / `KRBR_CACHE_DIR` で差し替えられます（テストで使用）。

### 材質システム

材質は OpenPBR Surface のパラメータで書きます（`krbr-scene` の `material.rs`、色はリニア）。分散は `transmission_dispersion_abbe_number` と `transmission_dispersion_scale` で指定し、`specular_ior` を nd として扱います。アッベ数で表せない材質は、`[material.<名前>.krbr]` に Sellmeier の係数（`sellmeier_b`, `sellmeier_c`）を書けます。

**金属**のフレネルは OpenPBR の F82-tint です（`base_color` が正面の反射率 F0、`specular_color` が 82° での色味。Schlick の近似に対する比）。`[material.<名前>.krbr]` に `conductor = "Au"` のように書くと、**測定値の複素屈折率 n + ik** の金属になります。

- 分光モードでは、波長ごとの n, k から厳密なフレネルの式で反射率を求めます（`shaders/bsdf.glsl` の `fresnelConductor`）。
- RGB モードでは、同じ表から求めた F0 と F82-tint を使います（反射率のスペクトルを、分光モードと同じ等色関数・白色点で RGB にしたもの）。白い炉の中で両者の色の差は 1〜3% です。
- 表は `krbr-scene/src/conductor_data.rs` で、`scripts/gen_conductors.py` が refractiveindex.info のデータベース（CC0。コミットを固定）から 360〜830 nm を 5 nm 刻みで作ります。
- 測定値の金属の色は測定値から決まるので、`base_color` / `specular_color` / `base_metalness` を書くと測定値の金属ではなくなります（`conductor = "none"` でも外れる）。

| ID | 金属 | 出典 |
|---|---|---|
| `Au` / `Ag` / `Cu` | 金・銀・銅 | Johnson & Christy 1972 |
| `Cr` / `Ni` / `Fe` / `Co` / `Ti` / `Pd` | クロム・ニッケル・鉄・コバルト・チタン・パラジウム | Johnson & Christy 1974 |
| `Al` | アルミニウム | Rakić 1995 |
| `Pt` | 白金 | Rakić et al. 1998（Brendel-Bormann のモデル） |
| `Rh` / `W` | ロジウム・タングステン | Weaver et al. 1977 / 1975 |
| `Os` | オスミウム | Nemoshkalenko et al. 1968（常光線と異常光線の誘電率を 2:1 で平均した多結晶） |
| `Zn` | 亜鉛 | Werner et al. 2009（Querry 1987 の値は可視域の n が 9〜14 と金属の値に見えないので使わない） |
| `CuZn30` / `CuZn15` | 真鍮・丹銅 | Querry 1985 |
| `SS_austenitic` | ステンレス鋼（オーステナイト系） | Karlsson & Ribbing 1982 |

錫は可視域の測定値が見つからない（refractiveindex.info は 0.73 µm から）ので、`metal_tin` は F0 の色で決めた金属です（組み込みの規則で割り当てると、3D モデルの面の色が部位の色の調整として付きます）。

**組み込みの材質**（`krbr-scene/src/builtin_materials.toml`。`krbr material list` で一覧）は、分類（`[krbr] category`：metal / plastic / rubber / ceramic / glass / other）ごとに並べています。表示名は `krbr-app/i18n/*/krbr-app.ftl` の `matname-<名前>` です。材質エディタで作った自分の材質は、重ならない ID（`user_` と 16 桁の 16 進）をキーにして、表示名を `[krbr] label` に書きます。部位への割り当て（設定ファイル）は ID で書くので、名前は後から変えられます（ほかの基板の割り当てもそのまま）。

- 金属：上の表の金属すべて（クロム・ニッケル・ステンレスはサテンの版も。サテンは粗さ 0.3〜0.35 の等方的な面で、ヘアラインの向きは表さない）と錫
- 樹脂：ABS・ポリカーボネート・PBT・ナイロン（PA66）・ポリアセタール（POM）・PP・PVC・PET・PTFE と、これまでの `plastic` / `glossy_plastic` / `epoxy_black`。どれも自分の色を持ち、部位ごとに `+color=` で変えられます。屈折率は、分散式のあるもの（PC：Sultanova et al. 2009）はその係数、測定値の見つかったもの（PVC・PET：Zhang et al. 2020）は nd、ほか（ABS・PBT・PA66・POM・PP・PTFE）はデータシートの代表値です
- ゴム：シリコーンゴム（PDMS：Schneider et al. 2009）、黒いゴム
- セラミック：`ceramic`、アルミナ（屈折率はサファイアの常光線：Malitson & Dodge 1972）
- ガラス・透明：アクリル（PMMA：Sultanova et al. 2009）、ポリカーボネート、透明シリコーン、透明な PET（Zhang et al. 2020 の表からアッベ数 28）、BK7（SCHOTT N-BK7）、石英ガラス（Malitson 1965）、ソーダ石灰ガラス（Rubin 1985）、無色のサファイア。すりガラス（ソーダ石灰ガラス、粗さ 0.35）とすりガラス調のアクリル（粗さ 0.3）は、表面の粗い透明な材質です（屈折して通るが像がぼける）
- 宝石：ダイヤモンド（Peter 1923）、ルビー・青いサファイア（コランダム：Malitson & Dodge 1972 の常光線）、エメラルド（ベリル。nd 1.577 と B–G の分散 0.014 からアッベ数 70.5）、キュービックジルコニア（Wood & Nassau 1982）。屈折率・分散は測定値か宝石学の値で、B–G（430.8〜686.7 nm）の分散はダイヤモンド 0.044、コランダム 0.018、キュービックジルコニア 0.060 と宝石学の値に合っています。色は代表的な宝石の色を「4 mm 進んだときの透過の色」として与えた目安です（吸収スペクトルの測定値ではない）。色は厚みで変わり、大きな部品ほど濃くなります
- 樹脂の `plastic_pet` などは、着色した成形品として不透明です（PET・PP・PC の樹脂そのものは透明か半透明。透明なものは「ガラス・透明」に入れてある）

材質エディタの見本の球は、直径 4 mm の球の見え方です（吸収の深さを、描く球の大きさとの比で伸ばしている）。

木材は、木目の模様を描く仕組みがまだ無いので入れていません。

```toml
# %APPDATA%\krbr\materials\my.toml
[material.epoxy_matte]
base_color = [0.02, 0.02, 0.02]
specular_roughness = 0.6
[material.epoxy_matte.krbr]
bump_pattern = "noise"
bump_strength = 0.015
bump_scale = 0.1
```

3D モデルの部位（STEP の XDE の名前と面の色、VRML の Material の DEF の名前と diffuseColor）ごとに、次の順で材質を決めます。

1. 部品番号ごとの上書き（基板の設定ファイル `<名前>.krbr` の `[ref.U3]`）
2. 3D モデルごとの上書き（`<名前>.krbr` の `[[model]]`）
3. 3D モデルごとの設定（全体の `model_map.toml` の `[[model]]`。他のプロジェクトと共有）
4. 色・名前の規則（全体の `model_map.toml` の `[[rule]]`、次に組み込みの規則）
5. 既定値

- 3D モデルは、展開前のパス（`path`）か、ファイル内容の XXH64（`hash`）のどちらかが一致すれば同じとみなします。ファイルを別の場所に移しても、中身が同じなら設定が効きます。
- 部位のキーは、XDE の名前、`kicad:<色名>`（KiCad 標準モデルの色。例 `kicad:metal_grey_pins`、`kicad:black_body`）、`#rrggbb`（STEP・VRML に書かれた色）です。KiCad 標準モデルの VRML（KiCad 8 まで）は STEP と同じ色の値なので、同じ `kicad:<色名>` になります。`"*"` は全部位に一致します。
- 材質はどれも自分の色を持ちます（3D モデルの面の色は使わない）。規則に `model_color = true` と書くと、3D モデルの面の色を部位の色の調整（`+color=`）として付けます。組み込みの規則のうち、汎用の樹脂・つやのある樹脂・セラミック・錫の規則はこれで、ボードを開いたときはモデルどおりの色に見えます。部位に別の材質を割り当てると、その材質の色になります。
- 組み込みの規則の先頭は、KiCad 標準のアルミ電解コンデンサのモデル用です（ファイル名が `CP_Radial_D*` / `CP_Elec_*`）。金属色の部位（缶と上面）を `aluminum`、ラジアルの帯（`kicad:light_brown_body`、スリーブへの印刷）を `plastic` にします（色で決める規則だけだと、上面が錫、帯がセラミックになるため）。タンタル（`CP_Radial_Tantal_*`）は対象外です。
- 材質名の後ろに `+smooth` を付けると、表面の模様（凹凸と粗さのむら）を無くした版になります（例 `plastic+smooth`。`krbr material set --material plastic+smooth`、ビューアの部位ごとの「模様」のチェック）。
- 材質名の後ろに `+color=#rrggbb`（sRGB）を付けると色を、`+rough=<0〜1>` を付けると粗さ（`specular_roughness`）を変えた版になります（例 `plastic_abs+color=#c03020+rough=0.25`。ビューアの材質エディタの「この部位だけの調整」）。色は、不透明な材質では地の色、透明な材質では透過の色、金属では F0 です。測定値の金属に色を付けると、測定値ではなくその色の金属（Schlick）になります。組み立ての順は `+smooth`、`+color=`、`+rough=`、`+emit=` で、同じ指定が 2 つあれば後ろのものが勝ちます。
- 材質名の後ろに `+emit=#rrggbb,<輝度>` を付けると、その色（sRGB。`#` は省略可）と輝度（cd/m²）で光る版になります（LED の点灯など。例 `plastic+emit=#ff0000,5000`。`+smooth` と組み合わせられる）。部品ごとに別の色にするなら、部品番号ごとの上書きに書きます（`krbr material set <pcb> --ref D4 --part kicad:white_body --material "plastic+emit=#ff0000,5000"`、ビューアの部位ごとの「発光」のチェック）。光るのは面の表側だけで、周りの基板や部品も照らします。KiCad 標準の `LED_0603_1608Metric` などでは、光らせる本体は `kicad:white_body` です（`kicad:green_body` は外から見えない部位）。
  - 光っている部位の地の色（拡散の反射率）は、発光の色にします（最も明るい成分を 0.7。色のついた拡散レンズ）。白い地のままだと、周りの光を白く返して発光の色が薄まるためです。
  - 明るさの目安（露出 0.7 EV）：1000〜2000 で色を保ったまま点灯して見え、上げるほど芯がオレンジ〜白に寄ります（ACES のトーンマッピングは、明るすぎる色を白へ向かわせる。実際のカメラで撮った LED と同じ）。グロー（下記）でにじませるには、しきい値（既定 4）を超える明るさが要ります。ビューアで発光を付けたときの既定は 5000 です。
- **透過（`transmission_weight`）**：ガラス・アクリルのような誘電体の屈折（粗さのある GGX の透過、Walter et al. 2007）。中では `transmission_color` / `transmission_depth` で吸収されます（depth が 0 なら、面を通るたびに色をかける）。閉じた形状で、面の向き（三角形の巻き方）が外向きであることを前提にしています。
- **subsurface**：krbr では簡易な形で扱います。`subsurface_weight` の割合で光が拡散して中へ入り、`subsurface_radius`（mm）進むと `subsurface_color` の透過率になる吸収を受けながら進み、反対側の面やふちから拡散して出ます（FR4 の透光性に使用）。
- fuzz・thin_film・anisotropy・geometry_opacity・thin_walled・transmission_scatter は値を GPU まで渡していますが、描画には反映していません（使われるとログで知らせます）。発光（`emission_luminance`、cd/m²）は、放射輝度 1.0 = 1000 cd/m² として描きます。発光は片面（三角形の巻き方で決まる表側）から、余弦分布で放たれます。発光する三角形は光源として直接サンプリングします（輝度 × 面積に比例して選ぶ）。

## そのほかの機能

**グロー（光のにじみ）**：点灯した LED など、とても明るい光が周りへにじむ様子を、トーンマッピングの前に足します（`krbr-render` の `glow.rs` と `shaders/glow.comp`）。Blender の Glare（Fog Glow）や Unreal の Bloom と同じ考え方の後処理で、光った物が「光って見える」のは主にこのにじみによります。

- 露出をかけた後の RGB の最も明るい成分がしきい値を超えた分だけを、半分ずつ縮めた画像の段（ピラミッド。最大 8 段、一番小さい段の短い辺が 4 画素以上）でぼかし、色を保って重ねます（Jimenez 2014 の方式）。輝度ではなく成分の最大で比べるので、色の濃い光（赤い LED）も白く飛ぶ前からにじみます。
- 3 つの値で調整します。どれも基板ごとに覚え、表示と、保存する PNG（`S`・`render`・`watch`）の両方にかかります（EXR（リニア）にはかからない）。

| パネル | コマンドライン / `<名前>.krbr` の `[render]` | 既定 | 内容 |
|---|---|---|---|
| グロー | `--glow` / `glow` | 1 | 強さ。にじんだ光の量（しきい値を超えた分に対する割合）。0 でなし |
| しきい値 | `--glow-threshold` / `glow_threshold` | 4 | これより明るい光だけがにじむ（露出をかけた後の値。1 が画面の白）。白い基板・部品や、環境マップの映り込みまで光るときは上げる |
| 広がり | `--glow-spread` / `glow_spread` | 0.7 | 段を 1 つ大きくするごとの重み（0..1）。小さいと光のすぐ近くに締まり、1 で画面の大きさ近くまで薄く広がる。にじんだ光の総量は変わらない |

- 発光の輝度としきい値の関係：発光面の明るさは、画面の白の「輝度 ÷ 1000 × 2^露出」倍です（5000 cd/m²・露出 0.7 EV なら約 8 倍）。これがしきい値を超えるとにじみます。
- 表示（GPU）と保存（CPU）は同じ式で、画素の差は 1/255 以内です（`tests/glow.rs`）。
- ぼかしの広がりは画像の大きさに比例するので、表示と、解像度の違う保存の画像でも見た目はそろいます。

**はんだフィレット**（`<名前>.krbr` の `[solder] fillet`（既定 true）・`material`（既定 `metal_tin+rough=0.15`）、`--no-fillet`）：部品の 3D モデルとパッドから、はんだの盛り（濡れ広がって凹んだ形）を作ります（`krbr-scene` の `solder.rs`）。

- 表面実装の部品は、ペーストの層（`F.Paste` / `B.Paste`）のあるパッドに作ります。体積はパッドの面積 × メタルマスクの厚み 0.12 mm × 0.5（溶けた後に残る割合）で、電極・リードの高さの 8 割まで登ります。チップ部品の電極、ガルウィングのリードのつま先とかかと、裏面の部品にも付きます。
- スルーホールの部品は、ピンの周りに円すい形の盛りを作ります（はんだ面が高く、部品面は低い）。
- 3D モデルの無い部品（代替の箱）、DNP で外した部品、何も載っていないパッド、モデルのリードがパッドに届いていない部品には作りません。はんだが部品やリードを突き抜けることはありません。
- 表示はパネルの「はんだフィレットを表示」かメニューの「表示」で切り替えます（形は作ったままなので、すぐ切り替わる）。部品の種類（表面実装・スルーホール）を隠すと、そのはんだも隠れます。クリックしても選べません。
- 保存の監視中は、パッドもモデルも動いていない部品のはんだを作り直しません。

**背景を透明にする**（設定パネルの「照明」、`--transparent` / `--opaque`、`<名前>.krbr` の `[render] transparent_background`）：カメラから見て環境マップしか見えない画素を透明にします（Blender の Film → Transparent と同じ考え方）。製品写真や資料に、基板だけを切り抜いた画像を使うときに。

- 環境マップは、照明と映り込みにはそのまま使います。基板の取り付け穴など、向こう側に何も無い所も透明になります。
- ビューアでは透明な所を市松模様で見せます。保存する PNG（`S`・「PNG として保存」・`render`・`watch`）はアルファ付き（ストレートアルファ）、EXR は A にアルファを入れ、色はアルファを掛けた値（premultiplied）にします。
- アルファは、画素の中のサンプルのうち、カメラの光線が何かに当たった割合です。縁はなめらかに半透明になります。ノイズ除去した画像にも、元の画像のアルファを付けます。
- ガラスなどの透明な物体は、不透明として扱います（向こうの景色は透けて見えるが、アルファは 1）。
- グローは物の上にだけかかり、透明な所には広がりません。
- MP4 は透明にできないので、動画の書き出しの間は背景を描きます。

**前回の設定を覚える**：ビューアのパネルで変えた設定は、基板の設定ファイル `<名前>.krbr` の `[remembered]` に覚え、次に開いたときにも使います（変えてから 1 秒後と終了時に書く）。同じファイルの手で書く表（`[render]` など）は書き換えません。

| 覚える項目 | 単位 | render / watch にも使うか |
|---|---|---|
| 環境マップ（ファイル・強さ・回転）、背景を透明にするか、露出、グロー（強さ・しきい値・広がり）、積分器、レンズ（種類・F 値・ピント・焦点距離・羽根・周辺減光・口径食・色収差）、色の計算（RGB / 分光）、凹凸の強さ、レジストの色、画角 | 基板ごと | 使う |
| 視点（注視点・距離・仰角・方位） | 基板ごと | 使う（`--look-at` / `--zoom` を付けたら自動の構図、`--elevation` / `--azimuth` はコマンドラインが勝つ） |
| ノイズ除去のオン・オフと強さ、最大 spp、表示モード（画像 / アルベド / 法線）、レンダリングの比率、表面実装・スルーホールの部品とはんだフィレットの表示 | 基板ごと | ビューアだけ |
| 描画のサイズ（決まったサイズのとき） | 基板ごと | 使う（`--width` / `--height` が勝つ） |
| ウィンドウの大きさ・位置・最大化、設定パネルを出すかとその幅 | 全体で 1 つ | ―（`--width` / `--height` を付けたらその大きさ。前回の位置が今の画面の外なら使わない） |

- 使う順番は、コマンドライン → 覚えたもの → 設定ファイル → 既定値です（`--rgb` は覚えた分光モードを打ち消す）。
- 項目ごとに覚えたときの設定ファイルの値も残し、後で設定ファイルのその項目を書き換えたときは、設定ファイルの方を使います。
- 一時停止と選んだ部品は覚えません（起動時から止めるなら `--paused`）。
- 「視点を戻す（R）」は、設定ファイルとコマンドラインの仰角・方位・画角での自動の構図に戻します。
- メニューの「表示」→「設定をすべて既定に戻す」で、パネルの設定と視点を設定ファイルとコマンドラインの値に戻し、その基板について覚えたもの（環境マップも含む）を消します。ウィンドウの大きさ・位置はそのままです。

**環境マップ**：`--hdr` は省略できます。次の順で決めます。

1. `--hdr`（`render` / `view` とも）
2. その基板で最後に使ったもの（`--hdr` で指定したもの、ビューアで選んだもの）
3. `<名前>.krbr` の `[environment] hdr`
4. 内蔵の **スタジオ**（`builtin:studio`）：灰色の撮影ブースに大きなソフトボックスを置いた環境を、その場で生成します（ファイル不要）。`--hdr builtin:studio` や `hdr = "builtin:studio"` でも指定できます

最後に使ったものは、基板ごとに `<名前>.krbr` の `[remembered]` に、最近使った一覧は `state.toml` に覚えます。覚えた後に `[environment] hdr` を書き換えたときは、そちらを使います。覚えたファイルが無くなっていたら 3・4 に戻ります。設定ファイルで指定したファイルが読めないときは、内蔵のスタジオで代えて続けます（`--hdr` で指定したものが読めないときはエラー）。ビューアの「環境マップ」の一覧には、内蔵のスタジオ、最近使ったもの、今のものと同じフォルダの `.hdr` / `.exr` が出ます。「開く...」でファイルを選ぶか、`.hdr` / `.exr` をウィンドウへドラッグ＆ドロップしても切り替えられます。

**線フォントの文字**：KiCad の線フォント（ストロークフォント）の文字は形の情報を持たないので、kicad-cli で SVG に書き出して取り込みます（`[kicad_cli] use_for_text` / `path`、`--no-kicad-cli`）。対象は krbr が描く外側の層（シルク・銅箔・ソルダーマスクの表裏）で、銅箔の文字は銅箔（凹凸と材質）に、マスクの文字はマスクの開口になります。内層と部品図の層などの文字は描きません。kicad-cli に渡すのは**それらの層に線フォントの文字（と文字の枠）だけを残した基板のコピー**です。TrueType の文字（`render_cache` を持つもの）はそれらの層から部品図の層へ移し、線・図形・パッドなどは取り除きます。TrueType の文字・線・図形は krbr が自分で描くので、kicad-cli の形が重なって太ったり二重になったりしません（この基板で、kicad-cli の有無で変わるのは線フォントの文字の画素だけであることを確かめています）。6 層は 1 回の `--mode-multi` でまとめて書き出します（kicad-cli の起動と基板の読み込みが時間の大半なので）。書き出すファイルの名前は層の表示名から決まり、表示名は基板や言語で変わるので、コピーの中で表示名を `KRBR_F_Cu` などに書き換えておきます。`--mode-multi` で出なかった層（古い kicad-cli）は、層ごとに `--mode-single` で書き出します。書き出しは `%LOCALAPPDATA%\krbr\cache\silk\<キー>-KRBR_F_Cu.svg` などにキャッシュします（キーは渡す基板のコピーの内容から作るので、TrueType の文字を動かしただけでは書き出し直しません。コピーを作るには基板全体を解析し直すので、元の基板の中身から引ける索引 `<元のキー>.key` も残し、同じ基板なら解析を省きます）。作業フォルダはプロセスごとに分け、kicad-cli は 120 秒で打ち切ります。保存で線フォントの文字が変わったときは、ビューアと `krbr watch` が裏で書き出し直し、終わったら凹凸タイルを全部作り直します（それまでは前の文字のまま。書き出し中にまた変わったら、終わった後にもう一度書き出します）。

**TrueType の文字の白抜き・角の丸い四角形**：`knockout` の文字（`(layer "F.Mask" knockout)` など）は、文字の向きにそろえた字の範囲に余白 max(線幅 / 2, 高さ / 9) を足した四角形を塗り、そこから字の形を抜きます（KiCad と同じ）。`gr_rect` / `fp_rect` の `radius` は角の丸みとして形にします。

**材質の CLI**：`krbr material list / show / set`、`krbr mask list`（上の「コマンド」の表）。`material set` は、書き込む先の `<名前>.krbr` / `model_map.toml` が既にあって書式の誤りで読めないときは、エラーで止めてファイルに触りません。全部位の指定（`--part` を省略、または `*`。ビューアの「まとめて選ぶ」）は、同じ書き込み先の部位ごとの指定も消して、本当に全部位をその材質にします。

**ビューアで材質を割り当てる**：3D 表示の部品を**クリック**すると選び（ドラッグは回転、Ctrl ＋クリックはピント合わせのまま）、輪郭線をオレンジで重ねます（画像には入りません。実レンズのときは投影が違うので出しません）。設定パネルの「選んだ部品」に、部位ごとの材質（材質ライブラリから選べる）と、決まった段階が出ます。書き込む先は「この部品」（`<名前>.krbr` の部品番号）、「このモデル」（`<名前>.krbr` の 3D モデル）、「全基板」（`%APPDATA%\krbr\model_map.toml`）から選び、材質を選ぶとすぐ書いて描き直します（`krbr material set` と同じ書き方）。「上書きを消す」で規則どおりに戻せます。部位の「発光」にチェックを入れると、その部位が光り（色の初期値は部位の色を最も明るくしたもの、輝度は 5000 cd/m²）、下の行で色（色の見本をクリック）と輝度を変えられます。色と輝度は、動かし終えてから 0.4 秒後に書き込んで描き直します。3D モデルが見つからない代わりの箱を選んだときは、探したパスと理由を出します。「輪郭線」のチェックを外すと、輪郭線を重ねません（細かい部品が並んでいて、輪郭線でかえって見にくいとき）。

**材質エディタ**（`M`、メニューの「表示」、パネルの「材質エディタ...」）：ビューアの中に別の窓を開きます（大きさを変えられ、どこにでも動かせる）。

- 左：分類ごとの材質の見本（市松模様の床の上の球。内蔵のスタジオの照明）と検索。選んだ部品の今の材質は、名前の色を変えて示します。クリックで選び、ダブルクリックか、部位の行・プレビューへの**ドラッグ＆ドロップ**で割り当てます。右クリックでメニュー（割り当て・複製・名前の変更・削除）。★は自分の材質です。「一覧」に切り替えると、小さな見本と名前・屈折率・粗さの行で並べます（見た目の似た材質を値で見比べる）。電子部品であまり使わない材質（ロジウム・パラジウム、BK7・石英ガラスなど）は、分類の中の「その他」に畳んであります（検索したときは全部出す）。見本は材質の色そのままで、割り当てるとその色になります。
- 見本の画像：組み込みの材質の見本は、16384 サンプル・ノイズ除去（OIDN）で焼き付けたものを exe に埋め込んであります（RGB と分光の両方）。自分の材質や色を変えた版はその場で描いてノイズ除去し、全体用キャッシュの `swatches\` に残します（材質のパラメータのハッシュで引くので、値が変われば描き直す。古いものから 500 枚を超えた分を消す）。
- 右上：選んだ部品だけを置いたプレビュー（ドラッグで回転、ホイールで拡大、ダブルクリックで戻す。ノイズ除去して見せる）。細かい部品でも、輪郭線なしで材質を確かめられます。その下に、書き込む先（この部品・このモデル・全基板）と、部位ごとの今の材質（見本つき）。割り当て先の部位を選びます（「（全体）」なら全部位）。部品を選ぶと、割り当て先の部位の材質が右下に出ます。
- この部位だけの調整：色（`+color=`）と粗さ（`+rough=`）。材質は増えず、同じ材質のままこの部位の見た目だけを変えます。動かすとプレビューにすぐ出て、止めてから 0.4 秒後に書き込んで 3D 表示も描き直します。「自分の材質として保存...」で、調整したものを名前付きの材質にできます。
- 割り当て先の部位に調整がある材質をパラメータの欄で開くと、欄の上に「この部位では 色 #rrggbb・粗さ 0.30 に調整している」と出し、上書きされている行に「部位の調整が優先」の印を付けます。「調整を材質に取り込む」で調整した値を材質の値にし（組み込みの材質ならコピーを作る）、「調整を外す」で材質の値に戻します。
- 右下：一覧で選んだ材質の説明（測定値の金属は出典、ほかは屈折率）と、「この部位に割り当てる」「複製して自分の材質にする...」「名前を変更...」（自分の材質だけ）、パラメータのパネル。同じ材質を割り当て直しても、部位の色・粗さの調整は残ります。
- パラメータは、Blender の Principled BSDF のように折りたためる節に分けて出します。種類（不透明・金属・透明）を選ぶと、その種類でレンダラが扱い物理的に意味のある項目だけを出し、ほかの種類の項目は矛盾しない値（例：金属なら透過 0）にします。種類を変えると、分類も合わせます。
  - ベース：物質（下記）、屈折率、色／透過の色とその色になる深さ／F0 と縁の色味（F82-tint）、粗さ、アッベ数（透明で分散式の無いもの）
  - 物質：金属は測定値の金属（上の表）か「カスタム」。不透明・透明は、ABS・PC・PBT・アクリル・シリコーン・アルミナ（サファイア）・BK7・石英ガラス・ダイヤモンドなどから、屈折率と分散（光学定数）だけを借ります（色と粗さはそのまま）。屈折率を手で変えると「カスタム」になり、分散式は同じ分散のアッベ数に置き換えます。
  - 半透明（不透明のみ）：光の一部が中へ拡散して入り、吸収されながら進む割合・色・その色になる距離（LED の拡散キャップ、白い樹脂）
  - クリアコート（不透明・金属）：強さ・粗さ・屈折率・色味
  - 表面の模様（不透明・金属）：なし・ノイズ・織り目、強さ・大きさ・粗さのむら
  - 元の値から変えた項目は名前に印（•）が付き、名前を右クリックすると元の値に戻せます。`Ctrl+Z` / `Ctrl+Shift+Z`（`Ctrl+Y`）とボタンで、元に戻す・やり直す（一続きの編集で 1 つ）。
  - 拡散の色が現実の範囲（反射率およそ 2〜90%）の外なら ⚠ を出します。
- 組み込みの材質は書き換えません。パネルの値を変えると、そのコピー（「〜 のコピー」）を自分の材質（全体設定の `materials/user.toml`）として作り、それを編集します。割り当て先の部位のうちその組み込みの材質のものは、コピーに付け替えます（KeyShot のライブラリの材質と同じ扱い）。
- 自分の材質の編集した値は、止めてから 0.4 秒後に `user.toml` に書き、使っている部位の材質だけを送り直します（形状は組み直さない）。発光を変えたときと、削除したときは、部位の材質を決め直します。
- 見本とプレビューは、ビューアと同じ GPU・同じ積分器（PT）で、色の計算（RGB / 分光）もビューアに合わせます。窓を閉じると GPU の資源を返します。

**一時停止**：ボタン列の「一時停止」（`P`、メニューの「表示」、起動時から止めるなら `--paused`）で、サンプルの積み足しを止めます。GPU の負荷がほぼ無くなるので、GPU の弱い PC でも操作できます。止めている間にカメラなどを変えたときは、表示のために 1 サンプルだけ描いて止まります。

**KiCad のプラグイン**：ビューアのメニューの「設定 → KiCad プラグイン...」で、PCB エディタのツールバーに「KRB Renderer でプレビュー」のボタンを足します。KiCad は版ごとに別のユーザーフォルダを使うので、見つかった版（9.0、10.0、nightly など）ごとに状態（未登録・登録済み・別の `krbr.exe` を指している・指している `krbr.exe` が無い・ファイルが古い）を出し、版ごとに登録・解除します。版は、ユーザーフォルダ（`KICAD_DOCUMENTS_HOME`、無ければ `ドキュメント\KiCad\<版>`。ドキュメントを OneDrive などへ移していればその場所）、レジストリのアンインストールの情報（`KiCad <版>` の `InstallLocation`）、`Program Files\KiCad\<版>` から探します。登録すると、その版の `scripting\plugins\krbr_preview` に、exe に埋め込んだ `kicad_plugin/krbr_preview` の中身と、この `krbr.exe` の場所を書きます。ビューアは起動のたびに、登録済みの版のうち、指している `krbr.exe` が無くなった版（フォルダを移した）と、ファイルが古い版（`krbr.exe` を更新した）を直します（未登録の版と、まだ有る別の `krbr.exe` を指している版には触らない）。コマンドラインでは `krbr kicad-plugin status`／`install`／`uninstall`（`--kicad 10.0` で版を、`--dir` で場所を指定。省くとすべての版）。登録の後は KiCad を開き直すか、PCB エディタの「ツール → 外部プラグイン → プラグインを再読み込み」で出ます。押すと、開いている基板のファイルをビューアで開きます（コンソールは出さず、ログは基板ごとに `%TEMP%\krbr_preview_<基板のパスのハッシュ>.log`。同じ基板のビューアが開いていれば二重には開かない。ビューアが起動の直後に終わってしまったときは、ログの場所を添えてメッセージを出す）。ビューアは保存を監視しているので、KiCad で保存するたびに描き直されます。旧来の Action Plugin（SWIG の `pcbnew`）を使っています。KiCad 9 で非推奨になり、KiCad 11 で無くなる予定なので、そのときは IPC API のプラグイン（`plugin.json`）に移します。

**exe のアイコンへのドラッグ＆ドロップ**：`krbr.exe`（またはそのショートカット）に `.kicad_pcb` をドロップすると、ビューアで開きます。作業フォルダは変えません（`S` で保存する画像は、起動の仕方によらず基板のフォルダに入り、ファイルのダイアログも基板・環境マップのフォルダから始まります）。エラーで終わるときは、コンソールが閉じる前に Enter を待ちます。

## 既知の制限

- 3D モデルは STEP と VRML 2.0（`.wrl`、gzip で圧縮した `.wrz`）を読みます。`.wrl` の指定は、同名の `.step` があればそちらを使います（形と部位の名前が正確なため）。逆に `.step` の指定でファイルが無く、同名の `.wrl` / `.wrz` だけがあれば VRML を読みます。
- VRML は、Shape の IndexedFaceSet だけを読みます（Transform・Group・Switch・LOD・DEF / USE は扱う）。基本形状（Box・Sphere・Cylinder・Cone）、線・点、Inline（別ファイルの参照）、テクスチャは読みません。VRML 1.0 は読めません（警告に出て、代替の箱になる）。単位は KiCad と同じく 1 単位 = 0.1 インチ（2.54 mm）です。
- パッドの `padstack`（層ごとに形が違うパッド）は、表と裏の形を使います。内層は描きません。
- 線フォント（KiCad 標準のストロークフォント）の文字は `render_cache` を持たないため、kicad-cli の SVG 出力から取り込みます（シルク・銅箔・マスク）。寸法線・表・バーコード（QR コードなど）も同じです。kicad-cli が無ければ、それらは描かれません（警告を出します）。
- レジストの縁の丸みは法線（見え方）だけで表し、形状は垂直な段差のままです。
- PT では、透明な物体は光源の直接サンプリングの光をさえぎります。透明な物体越しの光（集光模様、ガラスの下の明るさ）は収束が遅いので、サンプルを多めに積むか、VCM を使ってください（多重散乱の補償と同じく、MNEE やパスガイディングは今後の予定。`plan.md`）。
- 透明な物体は、閉じた形状で三角形の巻き方が外向き（表から見て反時計回り）であることを前提にしています。
- プロセスの終了時に、NVIDIA ドライバの GPU コンテキストの解放で数秒かかることがあります。この間、CPU と GPU はほとんど使いません。
